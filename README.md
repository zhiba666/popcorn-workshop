## 开发目标与运行平台

本项目要开发一款抖音小程序游戏，目标平台为抖音小游戏。交付目标是能够在抖音开发者工具中导入、编译和试玩，并支持抖音客户端真机预览。

Chrome 网页预览用于辅助开发和视觉检查；抖音平台兼容性与最终运行效果须通过抖音开发者工具和真机预览验证。

## 前期数值设计原则

前期优先完成核心玩法与流程。金币奖励、升级需求等影响游戏节奏的数值只设置简单、可调整的初始值，不做过多设计或精细平衡，也不围绕这些数值反复测试。验证以功能正常、无明显异常为准。

新增测试文件、测试用例或扩大既有测试的覆盖范围前，须说明验证目的、必要性及预计规模，并取得用户明确批准；一般开发授权不视为新增测试的授权。测试范围和数量应与当前任务的实际风险相称，优先复用已有覆盖，避免重复测试、提前覆盖尚未开放的功能，以及仅约束实现细节或未经确认数值的断言。运行已有测试，以及不扩大覆盖范围的修复、精简或合并，可在已授权任务内进行。

视觉设计属于开发任务。Codex 负责视觉方案、美术资源、界面实现和运行验证，依据设计书自主完成设计与修正；无需用户先提供参考图、尺寸或完整规范，也不把常规视觉问题留给用户反复指导返工。设计冲突、重大玩法取舍或无法解决的实现限制再集中说明。

### 界面原则

用场景、布局、动效和控件表达玩法，含义不明的图标保留短标签。主界面只显示当前决策所需信息，教学与详细规则按需展开，避免重复说明、宣传文案和无关实现细节。购买费用、效果、条件、操作后果及错误恢复必须清楚；以小屏运行效果验收，不靠缩小字号或挤压操作区容纳文字。

### 实施流程

1. **确定目标**：根据真实玩法与认可风格主动使用生图能力形成视觉目标，检查信息、操作与可实现性；已有适用目标直接复用。
2. **拆解与装配**：明确构图、比例、字体、间距和图层，复用或生成独立素材并接入资源构建；文字、数值与交互由程序实现，不把整张概念图当作 UI。
3. **实现代表画面**：先完成主要场景、核心信息和操作入口，对照目标还原，避免另起布局或用简单占位图替代必要美术。
4. **运行对照修正**：使用 Chrome，在相同视口、状态和内容下对照目标与真实截图，检查构图、色彩、层级、可读性及触控区域，主动修正明显差异。


### 验收与交付

视觉与功能分别验收，功能测试或 AI 审美评分不能证明视觉达标。概念图明确标注，只有实际运行截图能证明实现效果。交付展示目标与运行画面对照，说明差异、取舍及未验证内容；明显偏差先修正，不将大幅简化称为还原完成。用户反馈用于校准偏好，不替代 Codex 的设计与验收责任。
